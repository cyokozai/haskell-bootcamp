第3章の構文を復習する（5分）
----------------------------

第5章のコードには、第3章の構文がそのまま出てくる。

| 構文           | 例                                       | 意味                                  |
|----------------|------------------------------------------|---------------------------------------|
| パターンマッチ | `f [] = ...` / `f (x:xs) = ...`          | 引数の形で分岐する。上から順に試す    |
| ガード         | `\| even n = ...` / `\| otherwise = ...` | 条件で分岐する。`otherwise` は `True` |
| where          | `where isLong xs = length xs > 15`       | その定義の中だけで使う名前を付ける    |
| let            | `let a = 1 in a + 2`                     | 式の中で名前を付ける                  |
| `_`            | `zipWith' _ [] _ = []`                   | 使わない引数を表す                    |

`x:xs` は先頭の `x` と残りの `xs` に分けたリストを表す。`[1,2,3]` は `1:(2:(3:[]))` の略記である。

第4章 再帰（30分）
------------------

### 再帰とは

関数の定義の中で、その関数自身を呼び出すことを再帰と呼ぶ。問題を同じ種類の小さな問題に分けて解く。

再帰関数は2つの部分からできている。再帰せずに答えが決まる基底部（たいてい空リストや 0 のとき）と、小さくした問題を自分自身に解かせ、その答えを使って全体の答えを作る再帰部である。

### maximum'

```haskell
maximum' :: (Ord a) => [a] -> a
maximum' [] = error "maximum of empty list!"
maximum' [x] = x
maximum' (x:xs) = max x (maximum' xs)
```

要素が1つならそれが最大なので、3行目が基底部になる。4行目の再帰部は、先頭と残りの最大のうち大きいほうを返す。`maximum' [2,5,1]` は次のように展開される。

```text
maximum' [2,5,1]
= max 2 (maximum' [5,1])
= max 2 (max 5 (maximum' [1]))
= max 2 (max 5 1)
= max 2 5
= 5
```

`(Ord a) =>` は、`a` が大小を比較できる型であるという制約を表す。この制約があるので `max` を使える。

### 第4章のそのほかの再帰関数

```haskell
replicate' :: Int -> a -> [a]
replicate' n x
    | n <= 0    = []
    | otherwise = x : replicate' (n-1) x

take' :: Int -> [a] -> [a]
take' n _
    | n <= 0 = []
take' _ [] = []
take' n (x:xs) = x : take' (n-1) xs

reverse' :: [a] -> [a]
reverse' [] = []
reverse' (x:xs) = reverse' xs ++ [x]

repeat' :: a -> [a]
repeat' x = x : repeat' x

zip' :: [a] -> [b] -> [(a,b)]
zip' _ [] = []
zip' [] _ = []
zip' (x:xs) (y:ys) = (x,y) : zip' xs ys

elem' :: (Eq a) => a -> [a] -> Bool
elem' _ [] = False
elem' a (x:xs)
    | a == x    = True
    | otherwise = a `elem'` xs
```

`replicate'` は要素を1つ付けてから、残りの n-1 個を自分自身に作らせる。`reverse'` は残りを逆順にしてから、その末尾に先頭を付ける。`repeat'` には基底部がなく、無限リストを返す。

それでも `take 3 (repeat' 5)` が `[5,5,5]` で止まるのは、Haskell が遅延評価で、必要な3個しか計算しないからである。

### クイックソート

```haskell
quicksort :: (Ord a) => [a] -> [a]
quicksort [] = []
quicksort (x:xs) =
    let smallerOrEqual = [a | a <- xs, a <= x]
        larger = [a | a <- xs, a > x]
    in  quicksort smallerOrEqual ++ [x] ++ quicksort larger
```

先頭の `x` をピボットにし、残りを `x` 以下の要素と `x` より大きい要素に分ける。それぞれを再帰でソートし、間に `x` を挟んでつなぐ。

### 再帰関数の書き方

再帰関数は次の順で考えると書きやすい。

1.	再帰に頼らずに答えが決まる基底部から書く
2.	問題を小さな部分問題に分け、自分自身に解かせる
3.	部分問題の答えは正しいと仮定して、全体の答えを組み立てる

3番目のおかげで、全体の動きを最後まで追いかけなくても書ける。

5.1 カリー化関数（20分）
------------------------

### すべての関数は引数を1つしかとらない

`max 4 5` は、実際には2段階で計算される。まず `max 4` が、4 と比べて大きいほうを返す関数を作る。次に、その関数を `5` に適用して `5` を得る。GHCi で型を見ると、引数を1つ渡すごとに型が短くなることが分かる。

```haskell
ghci> :t max
max :: Ord a => a -> a -> a
ghci> :t max 4
max 4 :: (Ord a, Num a) => a -> a
```

型の `->` は右結合なので、`a -> a -> a` は `a -> (a -> a)` と読む。`a` を受け取って、`a -> a` という関数を返すという意味になる。一方、スペースによる関数適用は左結合なので、`max 4 5` は `(max 4) 5` と同じになる。

複数の引数をとる関数を、引数を1つ受け取って関数を返す関数の連なりとして扱うことをカリー化と呼ぶ。引数の一部だけを渡して、残りの引数を受け取る関数を作ることを部分適用と呼ぶ。

### multThree で確かめる

```haskell
multThree :: Int -> Int -> Int -> Int
multThree x y z = x * y * z
```

型は `Int -> (Int -> (Int -> Int))` と読む。引数を1つずつ渡すと、型と意味は次のように変わる。

| 式                | 型                         | 意味                 |
|-------------------|----------------------------|----------------------|
| `multThree`       | `Int -> Int -> Int -> Int` | 3つを掛ける          |
| `multThree 3`     | `Int -> Int -> Int`        | 3 と残り2つを掛ける  |
| `multThree 3 5`   | `Int -> Int`               | 15 と残り1つを掛ける |
| `multThree 3 5 9` | `Int`                      | 135                  |

GHCi で `:t multThree 3` などを打って確かめる。

### 部分適用で関数を定義する

```haskell
compareWithHundred :: Int -> Ordering
compareWithHundred x = compare 100 x
```

両辺の右端に同じ `x` があるので、消して次のように書ける。

```haskell
compareWithHundred = compare 100
```

右端の引数を消すこの変形は、5.5 と 5.7 でも何度も使う。引数を書かない書き方をポイントフリースタイルと呼ぶ。

### セクション

`+` や `/`、バッククォートで囲んだ `elem` などの中置関数は、片側だけ値を入れて括弧で囲むと部分適用できる。これをセクションと呼ぶ。

| セクション | 意味                  | 例                              |
|------------|-----------------------|---------------------------------|
| `(/10)`    | `\x -> x / 10`        | `(/10) 200` は `20.0`           |
| `(10/)`    | `\x -> 10 / x`        | `(10/) 200` は `5.0e-2`（0.05） |
| `(++ "!")` | 後ろに `"!"` を付ける |                                 |
| `("!" ++)` | 前に `"!"` を付ける   |                                 |

`elem` のような名前の関数も、バッククォートで囲めば同じようにセクションにできる。次の定義は、大文字かどうかを返す関数になる。

```haskell
isUpperAlphanum = (`elem` ['A'..'Z'])
```

ただし `(-4)` はマイナス4という数を表し、関数にはならない。4 を引く関数は `(subtract 4)` と書く。

### 関数は表示できない

```haskell
ghci> multThree 3 4
error: No instance for (Show (Int -> Int)) ...
```

`multThree 3 4` は `Int -> Int` という関数なので、GHCi はそれを文字列にする方法を知らない。引数が足りないときによく出るエラーなので、メッセージの形を覚えておく。

5.2 高階実演（15分）
--------------------

関数を引数にとる関数や、関数を返す関数を高階関数と呼ぶ。

### applyTwice

```haskell
applyTwice :: (a -> a) -> a -> a
applyTwice f x = f (f x)
```

型の括弧 `(a -> a)` で、第1引数が関数であることを表している。括弧がないと `a -> a -> a -> a` になり、3引数の関数という別の意味になる。

### zipWith'

```haskell
zipWith' :: (a -> b -> c) -> [a] -> [b] -> [c]
zipWith' _ [] _ = []
zipWith' _ _ [] = []
zipWith' f (x:xs) (y:ys) = f x y : zipWith' f xs ys
```

第4章の `zip'` と比べると、`(x,y)` が `f x y` に変わっている。要素の組をどう計算するかを引数 `f` で受け取るので、渡す関数を替えれば足し算にも連結にも使える。

### flip'

```haskell
flip' :: (a -> b -> c) -> b -> a -> c
flip' f y x = f x y
```

本来の型は `(a -> b -> c) -> (b -> a -> c)` だが、`->` が右結合なので右側の括弧は省ける。すると、関数 `f` と `y` と `x` の3つを受け取る関数と読めるので、上のように書ける。

```haskell
ghci> zipWith (flip' div) [2,2..] [10,8,6,4,2]
[5,4,3,2,1]
```

`flip' div 2 10` は `div 10 2` として計算されるので、結果は `div 10 2`、`div 8 2` と続く。

5.3 関数プログラマの道具箱（25分）
----------------------------------

### map と filter

```haskell
map :: (a -> b) -> [a] -> [b]
map _ [] = []
map f (x:xs) = f x : map f xs

filter :: (a -> Bool) -> [a] -> [a]
filter _ [] = []
filter p (x:xs)
    | p x       = x : filter p xs
    | otherwise = filter p xs
```

`map` はリストの全要素を関数で変換する。`filter` は、述語（`Bool` を返す関数）を満たす要素だけを残す。どちらもリスト内包表記で同じことを書ける。

| 高階関数                        | リスト内包表記                   |
|---------------------------------|----------------------------------|
| `map (+3) xs`                   | `[x+3 \| x <- xs]`               |
| `filter even xs`                | `[x \| x <- xs, even x]`         |
| `filter (<15) (filter even xs)` | `[x \| x <- xs, x < 15, even x]` |

どちらを使ってもよいので、読みやすいほうを選ぶ。

### 遅延評価と takeWhile

```haskell
largestDivisible = head (filter p [100000,99999..])
    where p x = x `mod` 3829 == 0
```

降順のリストを `filter` して `head` を取るので、最初に条件を満たす数が見つかった時点で計算が終わる。

`takeWhile p xs` は、先頭から `p` を満たす間だけ要素を取り出し、満たさない要素が来たら止まる。`filter` は最後まで探し続けるので、無限リストと組み合わせるときは `takeWhile` を使う。

```haskell
ghci> sum (takeWhile (<10000) (filter odd (map (^2) [1..])))
166650
```

この式は右から読む。`[1..]` の各要素を2乗し、奇数だけを残し、10000 未満の間だけ取り出して合計する。

### コラッツ列

```haskell
chain :: Integer -> [Integer]
chain 1 = [1]
chain n
    | even n = n : chain (n `div` 2)
    | odd n  = n : chain (n * 3 + 1)

numLongChains :: Int
numLongChains = length (filter isLong (map chain [1..100]))
    where isLong xs = length xs > 15
```

`numLongChains` は3段階で計算する。

1.	`map chain [1..100]` で 100本のコラッツ列（リストのリスト）を作る
2.	`filter isLong` で、長さが15より長い列だけを残す
3.	`length` で残った本数を数えると 66 になる

教科書の問題文は「長さ15以上」だが、コードは `> 15` になっている。講義ではコードに合わせる。`>= 15` にすると答えが変わるので、質問されたら説明できるようにしておく。

### 関数のリスト

```haskell
ghci> let listOfFuns = map (*) [0..]
ghci> (listOfFuns !! 4) 5
20
```

`(*)` に引数を1つだけ与えると1引数関数になる。そのため `map (*) [0..]` は `[(0*),(1*),(2*),...]` という関数のリストになる。

5.4 ラムダ式（10分）
--------------------

ラムダ式は、その場限りで使う名前のない関数である。`\引数 -> 本体` と書く。

```haskell
numLongChains = length (filter (\xs -> length xs > 15) (map chain [1..100]))
```

引数を複数とるときは `\a b -> (a * 30 + 3) / b` のように並べる。`\(a,b) -> a + b` のようにパターンマッチも書けるが、パターンは1つしか書けず、合わないとランタイムエラーになる。

部分適用で書けるときは、ラムダ式を使わない。`\x -> x + 3` より `(+3)` のほうが読みやすい。

カリー化のおかげで、次の2つの定義は同じ関数になる。

```haskell
addThree x y z = x + y + z
addThree = \x -> \y -> \z -> x + y + z
```

5.5 畳み込み（30分）
--------------------

この章で一番時間をかける節である。

### なぜ畳み込みを使うのか

第4章の再帰関数は、ほとんどが次の形をしている。

```haskell
f [] = 初期値
f (x:xs) = x と (f xs) を組み合わせる
```

組み合わせ方と初期値だけを渡せば同じ計算ができるようにしたものが、畳み込みである。

### foldl（左畳み込み）

型変数の名前を読みやすく変えると、`foldl` の型は次のようになる。

```haskell
foldl :: (acc -> x -> acc) -> acc -> [x] -> acc
```

```haskell
sum' xs = foldl (\acc x -> acc + x) 0 xs
```

`sum' [3,5,2,1]` は次の順に計算される。

| ステップ | acc | x | 新しい acc |
|----------|-----|---|------------|
| 1        | 0   | 3 | 3          |
| 2        | 3   | 5 | 8          |
| 3        | 8   | 2 | 10         |
| 4        | 10  | 1 | 11         |

ラムダ式 `\acc x -> acc + x` は `(+)` と同じである。さらに右端の `xs` を消すと、`sum' = foldl (+) 0` と書ける。

### foldr（右畳み込み）

```haskell
foldr :: (x -> acc -> acc) -> acc -> [x] -> acc
```

`foldl` とはラムダ式の引数の順番が逆になり、`\x acc` と書く。結果は右から畳んだように見える。

```text
foldr f z [3,4,5,6] = f 3 (f 4 (f 5 (f 6 z)))
foldl g z [3,4,5,6] = g (g (g (g z 3) 4) 5) 6
```

リストを作るときは `foldr` を使う。`x : acc` で先頭に付けていけば、要素の順番が保たれる。`foldl` で書くと `acc ++ [f x]` と末尾に付けることになり、`++` は左側のリストを毎回たどり直すので、長さ n のリストに n² に比例する時間がかかる。

```haskell
map' f = foldr (\x acc -> f x : acc) []
filter' p = foldr (\x acc -> if p x then x : acc else acc) []
elem' y = foldr (\x acc -> if x == y then True else acc) False
```

### foldl1 と foldr1

`foldl1` と `foldr1` は初期値を受け取らず、リストの最初（または最後）の要素を初期値にする。空リストに対して呼ぶとエラーになる。

```haskell
maximum' = foldl1 max
last' = foldl1 (\_ x -> x)
```

### 第4章の書き方と比べる

| 関数     | 第4章（再帰）         | 第5章（畳み込み）             |
|----------|-----------------------|-------------------------------|
| maximum' | `max x (maximum' xs)` | `foldl1 max`                  |
| reverse' | `reverse' xs ++ [x]`  | `foldl (flip (:)) []`         |
| elem'    | ガードで比較して再帰  | `foldr (\x acc -> ...) False` |

`reverse'` で `flip (:)` を使う理由を確認しておく。`(:)` は `x : acc` の順に引数をとるが、`foldl` に渡す関数は `\acc x` の順に受け取る。`flip` で引数の順を入れ替えれば、`(:)` をそのまま渡せる。

### foldr は無限リストでも止まることがある

```haskell
and' xs = foldr (&&) True xs
```

`and' (repeat False)` を展開すると `False && (False && ...)` になる。`&&` は第1引数が `False` なら第2引数を見ないので、最初の `False` で結果が `False` に決まる。遅延評価なので、残りは計算されない。

`foldl` は最後の要素まで見ないと結果を返せないので、無限リストでは止まらない。

### スキャン

スキャンは、畳み込みの途中経過をすべてリストにして返す。`scanl` では最後の要素が `foldl` の結果になり、`scanr` では先頭の要素が `foldr` の結果になる。

```haskell
ghci> scanl (+) 0 [3,5,2,1]
[0,3,8,10,11]
ghci> scanr (+) 0 [3,5,2,1]
[11,8,3,1,0]
```

```haskell
sqrtSums = length (takeWhile (<1000) (scanl1 (+) (map sqrt [1..]))) + 1
```

`sqrtSums` は 131 になる。平方根の和は単調に増えるので、`takeWhile` で 1000 未満の部分を切り出せる。1000 未満の和が 130 個あるので、131 個目で 1000 を超える。

5.6 `$` と 5.7 関数合成（25分）
-------------------------------

### `$`

```haskell
($) :: (a -> b) -> a -> b
f $ x = f x
```

意味は普通の関数適用と同じだが、優先順位が最も低く、右結合になる。`$` の位置から式の終わりまでを括弧で囲んだものと読めばよい。次の2つの式は同じ値になる。

```haskell
sum (filter (> 10) (map (*2) [2..10]))
sum $ filter (> 10) $ map (*2) [2..10]
```

`($ 3)` は、関数を受け取って 3 に適用する関数になる。たとえば `map ($ 3) [(4+), (10*)]` は `[7,30]` を返す。

### 関数合成 `.`

```haskell
(.) :: (b -> c) -> (a -> b) -> a -> c
f . g = \x -> f (g x)
```

合成した関数は右から順に適用する。`negate . sum . tail` は、`tail`、`sum`、`negate` の順に適用される。

`.` は関数と関数をつないで新しい関数を作り、`$` は関数を値に適用する。この違いで、次の1行目は正しく、2行目は型エラーになる。

```haskell
sum . replicate 5 $ max 6.7 8.9
sum . replicate 5 . max 6.7 8.9
```

1行目は、合成した `sum . replicate 5` を `max 6.7 8.9` の値に適用している。2行目では `max 6.7 8.9` が数（関数ではない）なので、`.` でつなげない。

### 括弧の多い式を書き直す手順

```haskell
replicate 2 (product (map (*3) (zipWith max [1,2] [4,5])))
```

この式は次の順で書き直せる。

1.	一番内側の関数と引数を書き出す：`zipWith max [1,2] [4,5]`
2.	その前の関数を `$` でつなぐ：`map (*3) $ zipWith max [1,2] [4,5]`
3.	さらに前の関数を `.` で合成する：`product . map (*3) $ ...`
4.	同じことを繰り返す：`replicate 2 . product . map (*3) $ zipWith max [1,2] [4,5]`

### ポイントフリースタイル

関数定義に現れる一時変数をポイントと呼び、ポイントを書かずに関数を定義する書き方をポイントフリースタイルと呼ぶ。

```haskell
fn x = ceiling (negate (tan (cos (max 50 x))))
fn = ceiling . negate . tan . cos . max 50
```

1行目の `x` は括弧の奥にあるので、そのままでは消せない。関数合成で書き直すと `x` が右端に出てくるので、消せるようになる。合成が長くなりすぎたら、`let` で途中の結果に名前を付けて分割する。
